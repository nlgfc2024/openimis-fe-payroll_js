# openIMIS Frontend Payroll module
This repository holds the files of the openIMIS Frontend Payroll module.
It is dedicated to be bootstrap development of [openimis-fe_js](https://github.com/openimis/openimis-fe_js) modules, providing an empty (yet deployable) module.

Please refer to [openimis-fe_js](https://github.com/openimis/openimis-fe_js) to see how to build and and deploy (in developement or server mode).

The module is built with [rollup](https://rollupjs.org/).
In development mode, you can use `npm link` and `npm start` to continuously scan for changes and automatically update your development server.

## Configurations Options

Payroll list columns and form fields can be hidden through the frontend module
configuration. The default is to show all columns and fields. Hidden required
fields remain visible until a configured default value is loaded.

```json
{
  "payroll": {
    "hiddenPayrollListColumns": [
      "name",
      "paymentPlan",
      "status",
      "paymentPoint",
      "paymentMethod"
    ],
    "hiddenPayrollFormFields": [
      "paymentPlan",
      "paymentPoint",
      "status",
      "paymentMethod"
    ],
    "defaultPaymentPlanId": "<payment-plan-uuid>",
    "defaultPaymentMethod": "StrategyOfflinePayment",
    "defaultPaymentPointId": "<payment-point-uuid>"
  }
}
```

`hiddenPayrollListColumns` applies to the all, pending, approved, and reconciled
payroll lists. Supported values are `name`, `paymentPlan`, `status`,
`paymentPoint`, and `paymentMethod`. `hiddenPayrollFormFields` applies to the
payroll detail form; supported values are `paymentPlan`, `paymentPoint`,
`status`, and `paymentMethod`. The payroll name is generated by the backend and
is not an editable form field.

Payment plan and payment method are required to create a payroll. When hidden,
provide `defaultPaymentPlanId` and `defaultPaymentMethod`; the configured plan
is loaded from the backend and used for creation. The payment point is optional,
and `defaultPaymentPointId` is optional. Use payment method names supported by
the instance's `paymentMethods` query. Payment cycle and valid-from/to dates
remain visible and required. Omitting these settings preserves the existing
form and list behavior.
